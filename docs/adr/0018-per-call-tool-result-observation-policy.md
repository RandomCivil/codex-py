# Per-call tool-result observation policy

**Status: accepted.** This amends ADR-0010 and ADR-0016. Tool-call batching remains the concurrent settlement boundary, but Runtime-context evidence is now retained per individual call: `list_dir` and `glob` retain raw results only while their Tool round is among the newest three; `grep` and `read_file` retain raw results for the invocation; and `apply_patch`, `write_file`, and write-class `exec` calls are asynchronously observed. This preserves exact long-lived read evidence, compacts writes without stalling either tool loop, and avoids treating unrelated calls in a concurrent batch as one context-lifecycle unit.

An observation-class call starts one no-tool, strict-schema Observation request after its batch settles, without delaying ReAct or the Plan-step Executor. Its Raw tool result is included while that request is pending; a validated Observation replaces it in subsequent context snapshots. Provider failure, cancellation, or invalid output is recorded diagnostically without retry and leaves the Raw tool result as permanent fallback. `list_dir` and `glob` never request Observations and are omitted once outside the newest-three-round window. `grep` and `read_file` never request Observations and remain Raw. Required Raw evidence is neither truncated nor re-summarized: a context that cannot fit it with Durable State fails; previously validated Observations may retain the existing synchronous budget-driven merge behavior.

`exec` uses a conservative static command classifier. Pure, top-level `ls`, `find`, and `fd` commands are the `list_dir`/`glob` class; pure, top-level `rg`, `grep`, `cat`, `sed`, `head`, and `tail` commands are the `grep`/`read_file` class. Top-level `apply_patch`, `tee`, `cp`, `mv`, `touch`, and commands containing redirection are write class. A pipeline, `&&`, `||`, `;`, subshell, variable expansion, unknown command, or other command that cannot be classified with certainty is write class. This policy applies identically to ReAct and the Plan-step Executor and does not alter Tool-call batch concurrency, request ordering, cancellation, persistence boundaries, or the nonblocking lifecycle of Observation tasks.

## Considered Options

- Retain and observe whole Tool-call batches — rejected because concurrent batches may mix calls with incompatible evidence lifecycles.
- Treat unknown or compound `exec` commands as read-only — rejected because static analysis cannot establish their effects or their appropriate evidence class.
- Evict, truncate, or re-summarize permanent Raw evidence to meet the token budget — rejected because it would lose the authoritative fallback for a failed Observation or a permanent-read result.
