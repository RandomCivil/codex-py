# Line Protocol model responses

**Status: accepted.** Every non-tool language-model response uses one locally validated Line Protocol contract, replacing provider-enforced `json_schema` and `json_object` configuration; legacy `response_format` values are rejected. The protocol uses matching, typed and nestable boundary lines, JSON-literal scalar values, dot paths for objects, repeated paths for scalar arrays, and repeated nested blocks for object arrays. Native function calls remain provider-native; when calls are present, the host executes them and ignores accompanying response text. Provider requests omit OpenAI `text.format` and LangChain `response_format`, while retaining native tool definitions and their parameter schemas. The host exposes decoded answers only after a complete protocol response passes validation. ReAct and Plan-step execution retain their separate completion request: a preceding tool-selection call with no native tool call must produce only an empty `NO_TOOL` protocol block. This trades provider schema enforcement for a provider-neutral text format while preserving strict local domain validation.
