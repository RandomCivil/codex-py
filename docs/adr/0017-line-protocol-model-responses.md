# Line Protocol model responses

**ReAct amendment:** ADR-0021 supersedes this ADR's ReAct no-tool response and Completion judge protocol statements. ReAct now uses `REACT_DECISION` and judgment only after a no-tool `completed` proposal.

**Earlier amendment:** The opening universal non-tool requirement was relaxed for ReAct and Plan-step Executor execution models when they returned no native tool calls. ADR-0021 replaces that ReAct exception with a strict `REACT_DECISION`; the Plan-step Executor exception remains. Structured Completion judge responses continue to use Line Protocol.

**Status: accepted.** Every non-tool language-model response uses one locally validated Line Protocol contract, replacing provider-enforced `json_schema` and `json_object` configuration; legacy `response_format` values are rejected. The protocol uses matching, typed and nestable boundary lines, JSON-literal scalar values, dot paths for objects, repeated paths for scalar arrays, and repeated nested blocks for object arrays. The parser accepts case-insensitive boundary and field names and either a space or underscore between `BEGIN`/`END` and a block name; it normalizes those identifiers to uppercase before validation. Scalar values still require valid JSON literals. Native function calls remain provider-native; when calls are present, the host executes them and ignores accompanying response text. Provider requests omit OpenAI `text.format` and LangChain `response_format`, while retaining native tool definitions and their parameter schemas. The host exposes decoded answers only after a complete protocol response passes validation. Criterion-enabled ReAct appends current criterion status to every tool-round context. A separate tool-free completion judge returns `COMPLETION_PROGRESS` with zero or more distinct, new, in-range `COMPLETED_CRITERION` blocks based only on successful settled tool results and an `ALL_COMPLETED` boolean that must agree with host-recorded state. A true verdict requires a nonempty final `ANSWER`, which ends ReAct immediately. ReAct without supplied criteria retains its existing terminal-response contract. Plan-step execution retains its separate completion behavior. This trades provider schema enforcement for a provider-neutral text format while preserving strict local domain validation.
