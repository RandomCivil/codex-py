# Layered context for tool-capable model loops

**Status: accepted.** ReAct and the Plan-step Executor use the same runtime context window for every Model request: complete request parameters and ordered results for the three most recent Tool rounds, schema-validated Observations for every earlier Tool round, and applicable Durable State. The recent three rounds contribute raw results only; their Observations are held out until each round leaves that raw window. This retains near-term debugging evidence while bounding long-running context; raw results are transient and never become Step context or recovery state. Complete raw results remain eligible for explicit diagnostic tracing, but trace output is not Model context or recovery state. An Observation has a round number and three always-present arrays of tool-call-ID-attributed confirmed facts, reported errors, and model inferences. A no-tool, strict-schema Model request generates it after each Tool-call batch; that request counts toward Model use but not the tool-round budget, and failure to generate or validate it fails the active execution. The window has an explicit token budget, defaulting to 128,000 tokens and configurable per component: when necessary, the oldest Observations are combined by a same-component, no-tool, strict-schema Model request that preserves their round range and source IDs; its failure also fails the active execution. No cross-provider tokenizer contract is introduced: the configured budget is a policy limit, and a provider's oversized-input rejection fails the execution. ReAct remains ephemeral. Each Plan-step Executor invocation begins with no transient tool history and inherits only its Durable State: the Agent state plus successful prior Context updates. Its Raw tool results are process-memory-only and excluded from LangGraph Checkpoints; the durable `running` marker and a successful Context update remain recorded.

## Considered Options

- Keep the complete transcript for every round — rejected because unbounded raw tool output eventually dominates the useful context window.
- Persist raw tool results for recovery — rejected because interrupted work is unconfirmed and ADR-0004 limits recovery to trustworthy state.
- Summarize all tool results immediately — rejected because recent corrective actions need their exact arguments and outputs.
